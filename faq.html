FAQ

Design choices, explained.

Telepact intentionally favors explicit schema modeling and forward-compatible evolution patterns over convenience abstractions that typically become long-term liabilities.

Why have both optional and nullable fields?

Optional fields model absence (undefined-like shape), while nullable fields model explicit null values. The distinction matters for safe update semantics.

Why are nullable arrays/objects not supported directly?

Nullability uses ? suffixes on type strings, while arrays/objects are JSON syntax forms. Telepact treats null as empty for scalar-like fields and uses collection emptiness for arrays/objects.

Why no built-in 404-style error?

Telepact encourages expressing absence as data (for example empty optional values) rather than transport-style status abstractions.

Why no generic catch-all Bad Request error?

Telepact prefers precise error/data modeling. Custom request-invalid cases should be explicit union members beside Ok_.

Why are positional arguments unsupported?

Argument structs reduce accidental breaking changes and better support backwards-compatible API evolution.

Why no classic enum type?

Union tags with struct payloads cover enum-like behavior while preserving future extension space.

Why force response validation on servers?

Always-on validation protects ecosystem type safety and surfaces server bugs early rather than silently propagating malformed data.

If binary is needed, why not just gRPC?

Telepact supports compact binary but avoids exposing ABI field IDs in the API schema by negotiating IDs at runtime.

Why are non-Ok_ result tags treated as errors?

The result union has a clear convention: Ok_ for success, others for non-okay outcomes. Naming error tags explicitly improves readability.

Why must union tags map to structs?

Struct payloads keep each branch extensible, enabling backwards-compatible additions over time.

Why can’t @select_ omit function argument fields?

Function-typed payloads are used as link-like call templates. Omitting arg fields would undermine stable, reusable call targets.
