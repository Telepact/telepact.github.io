Motivation

Why teams choose Telepact.

Telepact is built around four principles: accessibility, portability, trust, and stability. The goal is to preserve API ergonomics without locking you into one transport or one toolchain profile.

Core principles

Accessibility

Participate with plain JSON and standard networking, then opt in to generated code and binary if needed.

Portability

Schema definitions become reusable currency for docs, completion, mocking, and code generation.

Trust + Stability

Ecosystem-governed behaviors and constrained schema patterns improve predictable integrations over time.

Design tradeoffs

REST

Highly accessible, but transport concerns leak into API design and constrain usage across non-HTTP boundaries.

gRPC

Strong performance and generated type safety, but heavier toolchains and tighter ABI/codegen coupling.

GraphQL

Excellent dynamic querying, but query-string tooling dependence and weaker defaults for binary workflows.

Telepact

Combines JSON-first accessibility, optional binary, and dynamic shaping while keeping transports abstract.
